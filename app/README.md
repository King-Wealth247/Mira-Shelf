# app/ — React Native frontend

Frontend only. **Never** bundle Supabase service-role key, AI credentials, or any server-side code here.

## Native project generation (Stage 0 / Phase 4)

This folder holds the source tree and config. The native `android/` and `ios/` projects are
generated by the React Native CLI on a developer machine (they are heavy and not committed as a
scaffold). Assumption **A-01**: this is a React Native **CLI (bare) TypeScript** project, Android first.

```bash
# From the repo root, generate the bare RN project into app/ (one-time), then wire it to this src/.
npx @react-native-community/cli@latest init MiraShelf --directory app --pm npm
# If the project turns out to be Expo-managed, re-verify every native module in Section 17.
```

## Source layout (Section 12)

```
src/
├─ screens/      auth/ user/ admin/ superadmin/
├─ components/   reusable UI: BookCard, ProgressRing, EmptyState, ErrorBanner …
├─ navigation/   AuthStack, UserTabs, AdminStack, RoleGate
├─ services/     thin wrappers over supabase (books, reading, chat, admin)
├─ lib/supabase/ client creation, encrypted storage adapter, typed DB definitions
├─ auth/         AuthProvider, session handling, role hook (UI hint only)
├─ hooks/        useBooks, useReadingSession, useChat …
├─ state/        react-query client, small UI stores
├─ reader/       EpubReader, HtmlReader, progress calculator, TOC drawer
├─ ai/           chat UI, citation rendering, message formatting
├─ theme/        tokens, light/sepia/dark themes, typography
├─ utils/ validation/  helpers, Zod schemas shared with Edge Functions
└─ types/        domain models
```

Android-specific work (Section 11.2): release signing + R8, `network_security_config` blocking
cleartext in release, `allowBackup=false`, deep-link intent filter for password reset,
Keystore-backed session storage, reader back-button handling, WebView runtime config.
